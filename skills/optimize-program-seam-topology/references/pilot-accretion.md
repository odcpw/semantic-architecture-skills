# Dispersion, PowerBI, and OOXML accretion

This reference records only project evidence that changed the reusable seam
workflow. It is not a generic claim that every repository has these failure
modes.

## Mechanisms that survived real use

| Observed failure or result | Reusable seam mechanism | Regression test or falsifier |
|---|---|---|
| Dispersion's declaration-only comparison initially looked correspondence-ready | Separate a plausible cut from executed artifact correspondence | A graph with command strings but no bound accepted claim/control receipt must retain proof deficit or fail validation |
| A later resolved input changed while the declared square did not | Bind every result to exact graph, candidate, evaluator, skill, source, and receipt identities | Changing a graph/candidate nonclaim or one input byte changes the canonical result identity |
| Metadata noise changed raw packages while the semantic decision did not | Keep forensic package identity separate from decision projection | Unconsumed diagnostics may change raw evidence but must not invent a new seam decision |
| A spare invocation padded apparent corpus coverage | Derive coverage only through decision-mandatory claims and their controls | Orphan seam evidence is invalid |
| Two claims could share one negative control | Require bijective claim/control ownership at both alias and receipt layers | A reused control ID or receipt fails before scoring |
| A same-version evaluator rebuild could reuse an old result | Bind output to current evaluator, skill manual, and normative procedure closure | `identity` hashes change after code, skill, or normative reference edits |
| A free-text source claim outran binary evidence | Require structured content source, observation manifest, and derived candidate-semantics identities | A branch label or evidence inherited after an assignment/replacement change is invalid |
| Equivalent repeated executions produced the same semantic state | Keep campaign stopping in Semantic Architecture and local search closure in Seam Topology | One exhaustive local pass may prove bounded Pareto stationarity; a repeat only confirms idempotence |
| The PowerBI resolver extraction had no strictly better one-move reassignment but retained legitimate tradeoffs | Preserve the Pareto frontier and name the enumerated generator | Stationarity means no dominating one-representative structural move among existing modules, not global optimality |
| The Dispersion split seam was Pareto-dominated yet useful as a proof surface | Predeclare the consumer decision instead of selecting a score post hoc | Every graph requires decision ID, consumer, retirement condition, source identity, and protected observations |
| OOXML CLI's 75 KiB top-level dispatcher looked like the next monolith, but its completed command-manifest research had already falsified a broader typed-routing migration as duplication without simplification | Bind prior accepted/rejected architecture decisions and challenge file-size heuristics before reopening a seam | A prior decision receipt changes graph identity; a large file alone cannot satisfy the selection rule or semantic evidence gate |
| OOXML mutation sites called strict validation but discarded a rejecting report, so invalid packages were published with success | Trace verdict dataflow and distinguish observer execution from acceptance authority | A mutation whose validator returns a rejecting report must fail and preserve its input |
| The first gate fix still wrote a distinct `--out` before validation and deleted a pre-existing destination on rejection | Treat destination state, artifact ownership, and commit point as protected observations | A sentinel at an existing destination survives rejection byte-for-byte |
| Destination-local staging initially leaked private stage paths in PPTX chart readback and skipped publication on one branch | Require valid-candidate committed-path readback and result-path checks in the transaction corpus | The public result names the committed destination, the destination exists, and no private stage path appears |
| DOCX, PPTX, XLSX, and VBA shared the same six-state mutation protocol while retaining family-specific implementation context | Use Behavioral Factorization to test a context-retained protocol fold, then require executed source evidence separately | The supplied finite factor is lawful across every reachable family/context state; source correspondence remains an observed claim |

## Campaign rule

Expose one user invocation, but allow adaptive internal passes:

1. Pin decision, source, protected observations, evidence manifests, evaluator,
   skill, providers, and finite generators.
2. Discover only candidates that could change the decision.
3. Reject infeasible candidates before comparing engineering costs.
4. Challenge each surviving semantic claim with an exclusive nearby negative
   control.
5. Apply one accepted migration edge and re-evaluate only affected evidence.
6. Retain counterexamples and explicit nonclaims in canonical state.
7. Let Semantic Architecture stop only when the declared retirement condition
   is satisfied and all applicable finite generators and evidence invalidations
   are exhausted at an unchanged campaign state.

Do not rerun an unchanged deterministic campaign. Reopen when the source,
decision, observation set, evidence, provider, bound, candidate grammar, or a
decision-relevant falsifier changes.

## What remains outside the seam scorer

`fold_graph.py` validates binding shape, exact rational graph arithmetic, and a
bounded local structural generator. It does
not execute commands, authenticate receipts, recover a complete source model,
or prove source-program equivalence. Use Semantic Architecture for executed
evidence and decision contracts, and Behavioral Factorization for supplied
finite equivalence/factor/recomposition claims.
